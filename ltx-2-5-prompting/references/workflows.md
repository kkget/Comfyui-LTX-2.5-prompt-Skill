# 工作流边界

只读取当前任务对应部分。来源编号见 [sources.md](sources.md)。这些提示词格式不表示用户已经安装或启用了相应节点、模型或服务。

## 首帧图生视频

依据 S1、S2：

- 有可访问图像时先检查图像；如果无法查看，明确当前依据的是用户描述，不声称已核对首帧。
- 保留实际主体、衣着、物体、构图和光照，写出从首帧开始的后续动作。没有图像时可以给条件草稿，不虚构图中细节。
- 默认连续单镜头。需要离开初始场景时，显式写切镜和新的构图。
- 动作和相机运动要与可见空间一致，避免突然出现未经说明的新物体。
- 用户指定音频时加入声音描述；不要把静态图像当成已有对白或环境音的证据。

## Prompt Enhancer

依据 S2 的 Using the Prompt Enhancer：

| 路径 | 指南说明 |
| --- | --- |
| 本地 `ltx-pipelines` | 可选的 `--enhance-prompt`，由额外的语言模型推理扩写提示词 |
| 官方 ComfyUI 模板 | 通过专用节点使用，可关闭；实际节点和连接以已安装模板为准 |
| 直接 API 请求 | 不使用本地 CLI 的 `--enhance-prompt`；若服务有其他增强功能，查该接口文档 |

短草稿、粗略创意或其他模型的提示词适合考虑增强。已经结构完整、需要精确保留镜头或台词的提示词，增强收益可能较小，可关闭以提交原文。

增强会多一次推理并增加延迟。能取得增强后文本时，检查人物、动作、台词、切镜和相机终点是否被改变；无法取得时，不声称已经检查。不要把“建议关闭”写成所有任务都必须关闭。

官方文档提及的可选时长预测会依据提示词中的动作节拍工作。要停顿就写停顿；若接口允许显式时长，也可给整个序列更多时间。不要假设它会自动补出未描述的等待或慢动作。

## Dub-It：已有视频的对白替换

依据 S1、S2。此模式需要源视频，目标是替换讲话内容，而不是生成新的场景。

```text
[Speaker] is speaking [Language/Accent], saying: "[Full dialogue]"
```

- 给出完整目标台词；模型跟随提供的文字，不代替用户自动翻译。用户明确要求翻译时，先完成目标语言文本再写配音提示词。
- 台词使用目标语言的原生文字，例如普通话使用汉字。英语视觉描述的默认习惯不适用于翻译对白。
- 当前指南描述的 beta IC-LoRA 不区分多个说话者；用户需要多人配音时先说明这一边界，并按实际工作流处理。
- 目标文本应接近原对白时长和音节长度，略长通常优于过短；过长可能漏词，过短可能说得慢且不自然。没有源音频时，不承诺已匹配时间。
- 可添加情绪或发声方式，不必扩写场景、衣服或运镜。

2026-09-30 核验时，官方列出的已验证语言为英语、法语、西班牙语、德语、俄语。中文原生文字是写法示例，不能据此宣称中文已得到官方验证，也不能推断其他语言一定不支持。用户要求中文时可以提供正确格式，并说明该验证范围。

## Video Editing IC-LoRA

S1 页面摘要建议：一个具体修改指令，使用正向的增添/替换表达，并指明改变什么、保留什么。核验时该页面正文没有展开完整 Video Editing 配置，因此这里只提供提示词层面的建议，不推断节点、参数或适配器兼容性。

自编示例：

```text
Replace the plain ceramic mug with a clear glass mug in the same position, preserving the person's hand motion, the tabletop, the lighting, and the original camera movement.
```

先明确源视频和编辑目标；不要把多个独立大改动塞进一次编辑。具体能否执行，取决于用户已选工作流及其当前官方说明。

## 参考运动与适配器

依据 S3：需要可重复的相机与三维几何时，可考虑深度条件 IC-LoRA 或相机运动适配器。写提示词时优先让已有运动控制负责相机路径，避免再写冲突的文字运动。

用户有意改变参考运动时，确认所选控制路径是否允许该变化，再调整控制或文字；不要假设文字一定会覆盖参考。

指南提到 dolly in/out/left/right、jib up/down、static 等预训练相机适配器，同时说明其发布检查点和 LTX-2.5 兼容性需要核对。不要把 `dolly left` 等适配器名当成通用参数，也不要把所有旧版 LoRA 当作兼容当前模型。

## 帧数、尺寸与接口

仅在用户询问本地原生管线参数时使用 S3 的约束：

```text
(F - 1) % 8 == 0
latent_frames = 1 + (F - 1) / 8
width % 32 == 0
height % 32 == 0
```

例如 `F=49`、`57`、`121` 满足帧数约束，`F=50` 不满足。以 25 fps 计算，49 帧的名义片长约 1.96 秒，121 帧约 4.84 秒。短片段要简化运动，或在允许范围内增加帧数。以上约束不代表这些值在所有管线、检查点或服务上都可用。

本地 `--num-frames` 与 API 的 duration/fps 选项属于不同接口。不要把帧数约束直接变成 API 请求格式，也不要从这些算式推断最大时长、分辨率或显存要求。只有核对用户具体版本后才给可执行命令。
